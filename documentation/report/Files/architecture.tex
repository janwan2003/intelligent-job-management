\subsection{Deployment topology}

IJM runs as a small distributed system.
The FastAPI \emph{API} (which also hosts the \texttt{ProfilingScheduler}, \texttt{JobDispatcher}, \texttt{NodeSlots} semaphores and the optimizer client) runs on the operator's machine.
A lightweight FastAPI \emph{worker} runs on every GPU node and owns the local Docker daemon.
PostgreSQL runs on one of the GPU nodes.
Communication is plain HTTP over SSH tunnels, so the API reaches each worker at a stable \texttt{http://localhost:800x} alias regardless of where it actually sits.
An optional GPUspb \emph{optimizer} HTTP service is reached from the API.

Single-process \texttt{docker compose} on the operator's machine is supported for development but is not the deployment target: any tradeoff between local-dev simplicity and distributed correctness resolves toward the distributed topology.

\subsection{Scheduling pipeline}

A single scheduling pass --- \texttt{\_schedule\_waiting\_jobs} in \texttt{app.py} --- handles every dispatch decision.  It is invoked whenever a job is submitted, a profiling run finishes, a slot is freed, or every 60~s by a watchdog.  Notifies are coalesced through a single \texttt{asyncio.Event} and rate-limited to at most one pass every five seconds so the cluster has time to apply the previous plan before the next one is computed.

The pass walks four phases under a single \texttt{schedule\_lock}:

\begin{itemize}
  \item[\textbf{Phase 0}] Sweep stale profile claims (rows in \texttt{profiling\_results} with \texttt{duration\_seconds IS NULL} whose owning instance no longer exists or was repurposed) and reset stuck \texttt{QUEUED} rows whose \texttt{assigned\_node} was set $\geq 30$~s ago without the worker advancing them.
  \item[\textbf{Phase 1b}] Call the optimizer (outside the lock for its 30~s HTTP timeout) and apply its assignments via conditional \texttt{UPDATE \ldots WHERE assigned\_node IS NULL}; collect its preempt list.
  \item[\textbf{Greedy fallback}] For \texttt{QUEUED} rows the optimizer did not place (typically rows still owing a profile run), the \texttt{ProfilingScheduler} picks one profile config or a profiled standard slot.
  \item[\textbf{Phase 1c}] If a row still has no slot and still owes a profile, find the cheapest set of low-priority \texttt{RUNNING} jobs whose eviction would free enough GPUs for the next unprofiled config (the \emph{profile-always} policy).
\end{itemize}

Outside the lock the pass spawns one task per preempt and one per dispatch.  Each dispatch goes through \texttt{JobDispatcher.dispatch\_with\_slot}, which acquires the destination's \texttt{NodeSlots} permit before sending \texttt{POST /jobs/\{id\}/run} to the right worker.  Permits are released when the worker emits a \texttt{NOTIFY ijm\_slot\_freed} carrying the freed \texttt{(node\_id, n\_gpus)} pair.

\subsection{State machine}

A job moves through the following states.  All transitions are driven by atomic conditional \texttt{UPDATE}s so concurrent stop / dispatch / completion paths cannot clobber each other's work.

\begin{center}
\footnotesize
\begin{tabular}{l l p{8.5cm}}
\hline
\textbf{From} & \textbf{To} & \textbf{Trigger} \\
\hline
\texttt{QUEUED}     & \texttt{PROFILING} / \texttt{RUNNING} & Worker Phase~1 atomic claim \\
\texttt{PROFILING}  & \texttt{QUEUED}     & Profile run finished; \texttt{is\_profiling\_run} flips to \texttt{false} \\
\texttt{RUNNING}    & \texttt{SUCCEEDED} / \texttt{FAILED} & Container exit \\
\texttt{RUNNING}    & \texttt{PREEMPTED}  & User \texttt{POST /jobs/\{id\}/stop?reason=user} \\
\texttt{RUNNING}    & \texttt{QUEUED}     & Auto-preempt \texttt{reason=auto}: clears \texttt{assigned\_node} so the next pass can place elsewhere \\
\texttt{PREEMPTED} / \texttt{FAILED} & \texttt{QUEUED} & \texttt{POST /jobs/\{id\}/resume} \\
\hline
\end{tabular}
\end{center}

Two distinct stop reasons separate \emph{user-initiated} preemption (sticky \texttt{PREEMPTED}, the user must explicitly resume) from \emph{scheduler-initiated} preemption (\texttt{QUEUED} with cleared assignment, picked up automatically on the next scheduling pass).  The worker enforces this distinction and is also responsible for ignoring stale \texttt{/stop} calls aimed at a row that has since been re-assigned to a different node.

\subsection{Concurrency invariants}

The control plane relies on three invariants, each defended in code:

\begin{itemize}
  \item \textbf{No GPU oversubscription.}  Every dispatch goes through \texttt{NodeSlots.acquire(node\_id, n\_gpus)}.  On startup the semaphores are reconciled from the DB (rows in \texttt{RUNNING}/\texttt{PROFILING} or \texttt{QUEUED} with an assigned node pre-acquire their permits).  A periodic drift watcher recomputes the authoritative count every five minutes and corrects any divergence.
  \item \textbf{No duplicate containers per row.}  Both the worker (Phase~1 claim, \texttt{running\_jobs[job\_id]} check) and the API (\texttt{dispatch\_tasks[instance\_id]} deduplication) refuse a second concurrent dispatch for the same instance.  The reaper that resets stuck \texttt{QUEUED} rows cancels any live dispatch task instead of double-releasing its permit.
  \item \textbf{Profiling is sacred.}  Auto-preempt (\texttt{\_preempt\_and\_release}) refuses to act on \texttt{is\_profiling\_run=TRUE}; profile-preempt (Phase~1c) filters victims by \texttt{status='RUNNING'} only.  Only an explicit user \texttt{/stop?reason=user} can cancel an in-flight measurement.
\end{itemize}

\subsection{Cross-node checkpoints and image variants}

Two GPU generations are supported.  The \texttt{matemagician} node is pinned to driver 418.x (CUDA 10.1 max), so it runs a separate \texttt{:legacy} image built on PyTorch 1.5.1 + Python 3.7.  Newer nodes run the default \texttt{:latest} image on PyTorch 2.6 + CUDA 12.4.  Checkpoints are saved in the legacy pre-1.6 torch serialization format on every node so that a job can resume across nodes regardless of which torch version produced the file.

The shared \texttt{data/} directory is mounted on every node via rclone over SFTP and contains:

\begin{itemize}
  \item \texttt{data/checkpoints/\{job\_id\}/} --- per-job checkpoints, mounted into the container at \texttt{/checkpoints};
  \item \texttt{data/runs/\{job\_id\}/} --- captured stdout (\texttt{output.log}) and TensorBoard artifacts, mounted at \texttt{/runs};
  \item \texttt{data/shared/data/} --- read-only dataset cache (MNIST, CIFAR-10), mounted at \texttt{/runs/data}.
\end{itemize}

Worker-side environment variables \texttt{WORKER\_GPU\_MODE} (\texttt{runtime} | \texttt{cdi} | \texttt{none}) and \texttt{IMAGE\_TAG\_OVERRIDE} let the same nodes\_config drive heterogeneous nodes: the polimi-gpu rootless daemon uses CDI device injection, matemagician rewrites \texttt{:latest} to \texttt{:legacy}, and a CPU-only sandbox can be added by setting \texttt{WORKER\_GPU\_MODE=none}.
