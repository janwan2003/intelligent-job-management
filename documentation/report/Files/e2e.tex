This section presents the~cost model and~two end-to-end scenarios on~the
two-node cluster, both probing how~GPUspb's \texttt{method=RG} proxy
behaves.  Scenario~1 (\emph{under-subscribed}, single type) isolates its
\emph{horizon-myopia}: an~urgent job is~parked on~a~slow but~free bundle
because its deadline overrun is~invisible at~the~next-event horizon.
Scenario~2 (\emph{full}: A40 held by~\texttt{cnn\_big} pins, P600 by~slack
\texttt{lstm-small}) shows the~same myopia under capacity pressure ---
no~preemptible bundle meets the~urgent deadline, so~the~proxy drops the
cheapest slack, parks the~job on~the~cheapest slow bundle, and~the~deadline
is~recovered only by~a~later migration onto~freed A40.  The~priority-aware
outcome is~emergent (\S\ref{sec:e2e-objective}): the~optimiser minimises
a~stateless plan cost, never reasoning about preemption or~migration.

\section{Objective and cost model}
\label{sec:e2e-objective}

IJM delegates standard-run placement to~GPUspb run with
\texttt{method=RG}.  We~report what that~optimiser \emph{actually}
minimises, since it~is~the~ground truth for~every placement we~observe:
per~scheduling decision, Random Greedy scores a~candidate plan with the
proxy \texttt{proxy\_function\_min} (\texttt{optimizer.cpp}):
\[
\begin{aligned}
\textsc{Cost}_\textsc{RG}={}&
  \sum_{\text{sched }j}\!\Big(r(b_j)\,\Delta t + w(p_j)\,[\,t_0{+}\Delta t-d_j\,]^{+}\Big)
  + \sum_{n}\texttt{cost}_n\,\Delta t \\
  &{}+ \lambda\!\!\sum_{\text{unsched }j}\!\! w(p_j)\,[\,t_0{+}T^{\mathrm{full}}_j-d_j\,]^{+},
\end{aligned}
\]
with indices $j$ (over~the~plan's scheduled/unscheduled jobs) and~$n$
(over~the~cluster's nodes), and~parameters ($[x]^{+}\equiv\max(0,x)$):
\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
  \item $\Delta t$~--- next-event horizon: the~soonest finish among the~plan's scheduled jobs;
  \item $t_0$~--- the~current time;
  \item $b_j,\,p_j,\,d_j$~--- job~$j$'s assigned GPU bundle, priority, and~deadline;
  \item $r(b)$~--- hourly rate of~GPU bundle~$b$ (Table~\ref{tab:e2e-rates}, left);
  \item $w(p)$~--- per-priority tardiness weight (Table~\ref{tab:e2e-rates}, centre);
  \item $\texttt{cost}_n$~--- per-node operating cost from \texttt{nodes\_config.json} (Table~\ref{tab:e2e-rates}, right), passed through in~the~optimiser request.  Note the~sum is~over~\emph{every} configured node: \texttt{compute\_nodeCost} charges $\texttt{cost}_n\Delta t$ whether or~not the~node hosts a~job (no~occupancy filter), so~this term gives no~consolidation incentive;
  \item $T^{\mathrm{full}}_j$~--- job~$j$'s full remaining run time on~its~\emph{slowest profiled bundle} (the~$\max$ over~the~job's measured configs, \texttt{get\_maxExecTime}), charged in~full and~\emph{not} clipped to~$\Delta t$;
  \item $\lambda$~--- unscheduled-job penalty multiplier, hard-coded to~$\lambda{=}100$ in~\texttt{proxy\_function\_min}.
\end{itemize}
Three features of~this objective (Table~\ref{tab:e2e-proxy-features}) drive
everything the~scenarios show.

\begin{table}[H]\centering\small

GPU/tardiness/node of~\emph{scheduled} jobs & only to~horizon $\Delta t$ & a~placement that~overruns a~far-off deadline still reads zero tardiness \emph{now} (horizon-myopia; Scenario~1) \\
\emph{Unscheduled} job & $\lambda{=}100\times$ \emph{full} worst-case tardiness & omitting a~tight high-priority job is~ruinous, a~slack low-priority one nearly free (drop-the-cheapest; Scenario~2) \\
Migration / preemption & no~term & the~plan is~scored alone, ignoring what runs --- in-proxy, eviction is~free \\\bottomrule
\end{tabularx}

\end{table}

\subsection{Judging the~proxy: an~idealised yardstick}
\label{sec:e2e-proxy}

\textsc{Cost}$_\textsc{RG}$ is~what the~optimiser minimises, but~it~is
a~\emph{per-decision} surrogate.  To~judge its~choices we~compare against
an~\emph{idealised} full-run cost~--- the~same terms, but~with tardiness
(and~GPU/node cost) measured at~each job's \emph{real} completion instead
of~at~$\Delta t$.  The~gap between the~two is~what the~scenarios expose:

\begin{itemize}[leftmargin=*,itemsep=3pt,topsep=2pt]
  \item \textbf{Horizon-myopia (free slot $\Rightarrow$ Scenario~1).}  Charged only to~$\Delta t$, tardiness reads zero while a~deadline is~still in~the~future at~the~horizon~--- so~the~proxy parks an~urgent job on~a~cheap, free, far-too-slow bundle rather than~faster hardware it~would have to~clear first.
  \item \textbf{Drop-the-cheapest (full cluster $\Rightarrow$ Scenario~2).}  When jobs exceed capacity, every plan leaves someone unscheduled, and~the~$\lambda{=}100$ penalty drops whoever is~cheapest to~omit~--- smallest $w(p)\,[\text{lateness}]^{+}$.  On~the~true per-epoch costs the~same myopia also governs \emph{which} preemptible bundle then absorbs the~urgent job (the~cheapest, not~the~least-tardy), so~Scenario~2 exhibits both effects.
  \item \textbf{Preemption is~a~side effect.}  The~objective is~stateless (\S\ref{sec:e2e-objective}): the~optimiser picks a~target plan, and~IJM realises it~by~stopping whatever the~plan dropped~--- the~optimiser never reasons about preemption.
  \item \textbf{\texttt{method=PR} would~differ.}  The~deadline-aware variant scores per-job \emph{real} finish times and~would dodge the~horizon-myopia.
\end{itemize}

\subsection{URGENT plan comparison}
\label{sec:e2e-s1-urgent}

We report what the~optimiser actually scored.  At~URGENT's submission
($t{\approx}7.7$\,min) the~whole P600 node is~free, and~\texttt{proxy\_function\_min}
ranks the~plan that~drops URGENT onto~that~free P600$\times$2 as
\emph{cost-minimal} --- the~run's \texttt{OPT RESP} logs its~cost
at~\$0.030 --- even though that~bundle overruns the~$+10$-min deadline by
$\sim$2.4\,h.  Table~\ref{tab:e2e-s1-proxy} shows why: the~proxy charges
every job only up~to~the~horizon $\Delta t={}$\texttt{first\_finish\_time}
(the~soonest finish in~the~plan), and~in~every cheap plan a~prio-4 patient
finishes first a~few minutes out~--- so~URGENT's tardiness, read at~that
horizon, is~exactly~zero on~every bundle except the~one that~makes URGENT
itself finish first.

\section{Reproducibility}

All figures and~tables derive from the~2026-06-25 run snapshots committed
under \texttt{documentation/report/e2e\_runs/2026-06-25/\{s1,s2\}/}:

\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
  \item \textbf{Committed artifacts}: \texttt{api.log}, \texttt{jobs.json},
    \texttt{profiles\_*.json}, \texttt{chart\_s\{1,2\}\{,\_predicted\}.tex}.
  \item \textbf{Per-bundle costs}: \texttt{profiling\_results.duration\_seconds}
    $\times$ the~hourly rates (Table~\ref{tab:e2e-rates}).  These runs use~the
    corrected profiler --- the~worker records the~runtime's own per-epoch
    compute time (warmup excluded), not~log-line arrival intervals
    (\texttt{worker/profiling.py}, \texttt{execution.py}).
  \item \textbf{Charts}: auto-generated from the~API log by
    \texttt{generate\_chart\_tex.py} (predicted overlay:
    \texttt{generate\_chart\_tex\_predicted.py}); every bar is~a~real log event.
  \item \textbf{Drivers}: \texttt{infra/e2e\_scenario.sh},
    \texttt{infra/e2e\_scenario\_2types.sh}; slots at~\texttt{GET /admin/slots};
    API logs via \texttt{docker logs ijm-api} (stack up~by~\texttt{infra/ijm up}).
\end{itemize}
