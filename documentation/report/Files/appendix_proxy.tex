IJM delegates standard-run placement to~the~external GPUspb
optimiser~\cite{filippini2023pathrelinking,filippini2024stochastic}
(run with~\texttt{method=RG}); it~does \emph{not} implement the~optimiser.
This appendix documents what that~proxy minimises and~a~\emph{horizon-myopia}
in~its objective that explains several placements in~Chapter~\ref{ch:e2e}
--- in~particular why an~urgent job is~sometimes parked on~slow-but-free
hardware.  The~behaviour is~a~property of~the~upstream proxy, not~of~IJM,
which faithfully realises whatever plan the~optimiser returns.

\section{Objective and cost model}
\label{sec:e2e-objective}

Per~scheduling decision, Random Greedy scores a~candidate plan with the
proxy \texttt{proxy\_function\_min} (\texttt{optimizer.cpp}):
\[
\begin{aligned}
\textsc{Cost}_\textsc{RG}={}&
  \sum_{\text{sched }j}\!\Big(r(b_j)\,\Delta t + w(p_j)\,[\,t_0{+}\Delta t-d_j\,]^{+}\Big)
  + \sum_{n}\texttt{cost}_n\,\Delta t \\
  &{}+ \lambda\!\!\sum_{\text{unsched }j}\!\! w(p_j)\,[\,t_0{+}T^{\mathrm{full}}_j-d_j\,]^{+},
\end{aligned}
\]
with indices $j$ (over~the~plan's scheduled/unscheduled jobs) and~$n$
(over~the~cluster's nodes), and~parameters ($[x]^{+}\equiv\max(0,x)$):
\begin{itemize}[leftmargin=*,itemsep=1pt,topsep=2pt]
  \item $\Delta t$~--- next-event horizon: the~soonest finish among the~plan's scheduled jobs;
  \item $t_0$~--- the~current time;
  \item $b_j,\,p_j,\,d_j$~--- job~$j$'s assigned GPU bundle, priority, and~deadline;
  \item $r(b)$~--- hourly rate of~GPU bundle~$b$ (Table~\ref{tab:e2e-rates}, left);
  \item $w(p)$~--- per-priority tardiness weight (Table~\ref{tab:e2e-rates}, centre);
  \item $\texttt{cost}_n$~--- per-node operating cost from \texttt{nodes\_config.json} (Table~\ref{tab:e2e-rates}, right), passed through in~the~optimiser request.  Note the~sum is~over~\emph{every} configured node: \texttt{compute\_nodeCost} charges $\texttt{cost}_n\Delta t$ whether or~not the~node hosts a~job (no~occupancy filter), so~this term gives no~consolidation incentive;
  \item $T^{\mathrm{full}}_j$~--- job~$j$'s full remaining run time on~its~\emph{slowest profiled bundle} (the~$\max$ over~the~job's measured configs, \texttt{get\_maxExecTime}), charged in~full and~\emph{not} clipped to~$\Delta t$;
  \item $\lambda$~--- unscheduled-job penalty multiplier, hard-coded to~$\lambda{=}100$ in~\texttt{proxy\_function\_min}.
\end{itemize}
Three features of~this objective (Table~\ref{tab:e2e-proxy-features}) drive
everything the~scenarios show.

\emph{Unscheduled} job & $\lambda{=}100\times$ \emph{full} worst-case tardiness & omitting a~tight high-priority job is~ruinous, a~slack low-priority one nearly free (drop-the-cheapest; Scenario~2) \\

\section{Judging the~proxy: an~idealised yardstick}
\label{sec:e2e-proxy}

\textsc{Cost}$_\textsc{RG}$ is~what the~optimiser minimises, but~it~is
a~\emph{per-decision} surrogate.  To~judge its~choices we~compare against
an~\emph{idealised} full-run cost~--- the~same terms, but~with tardiness
(and~GPU/node cost) measured at~each job's \emph{real} completion instead
of~at~$\Delta t$.  The~gap between the~two is~what the~scenarios expose:

\begin{itemize}[leftmargin=*,itemsep=3pt,topsep=2pt]
  \item \textbf{Horizon-myopia (free slot $\Rightarrow$ Scenario~1).}  Charged only to~$\Delta t$, tardiness reads zero while a~deadline is~still in~the~future at~the~horizon~--- so~the~proxy parks an~urgent job on~a~cheap, free, far-too-slow bundle rather than~faster hardware it~would have to~clear first.
  \item \textbf{Drop-the-cheapest (full cluster $\Rightarrow$ Scenario~2).}  When jobs exceed capacity, every plan leaves someone unscheduled, and~the~$\lambda{=}100$ penalty drops whoever is~cheapest to~omit~--- smallest $w(p)\,[\text{lateness}]^{+}$.  On~the~true per-epoch costs the~same myopia also governs \emph{which} preemptible bundle then absorbs the~urgent job (the~cheapest, not~the~least-tardy), so~Scenario~2 exhibits both effects.
  \item \textbf{Preemption is~a~side effect.}  The~objective is~stateless: the~optimiser picks a~target plan, and~IJM realises it~by~stopping whatever the~plan dropped~--- the~optimiser never reasons about preemption.
  \item \textbf{\texttt{method=PR} would~differ.}  The~deadline-aware variant scores per-job \emph{real} finish times and~would dodge the~horizon-myopia.
\end{itemize}

At~URGENT's submission ($t{\approx}7.7$\,min) the~whole P600 node is~free,
and~\texttt{proxy\_function\_min} ranks the~plan that~drops URGENT
onto~that~free P600$\times$2 as~\emph{cost-minimal} --- the~run's

overruns the~$+10$-min deadline by~$\sim$2.4\,h.  Table~\ref{tab:e2e-s1-proxy}

on~every bundle except the~one that~makes URGENT itself finish first.
