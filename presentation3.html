Architecture — Three Deployment Modes

One codebase, three ways to run. Executor abstraction handles local; JobDispatcher routes to remote workers via HTTP.

Local dev :8000 :5173

API + JobRunner + DockerExecutor all in one process. Containers run locally.

Tunnel (current) SSH

API + frontend on laptop; postgres + worker on matemagician. SSH forwards :5433, :8001.

Multi-node scalable

One worker per GPU node; set workerUrl in nodes_config. API dispatches via HTTP.

Scheduling flow

Job submitted → greedy: assign to profiling node
                 ↓
Profiling completes (NOTIFY)
                 ↓
Optimizer called with ALL active jobs + currentScheduling
                 ↓
Preempts low-priority running jobs if needed for deadline-urgent ones
                 ↓
JobRunner/Dispatcher enqueues assigned jobs

Optimizer Integration (GPUspb)

External C++ optimizer (Flask wrapper on :8080). Called on every profiling-complete / job-complete event.

Request sent

  • jobs: all active jobs with profiling data
  • currentScheduling: what's running now
  • nodes: free GPUs (minus running jobs)
  • GPUcosts: energy cost table
  • method: RG (Randomized Greedy)

Response used

  • assignments: where each job should run
  • preempt: jobs dropped from currentScheduling
  • expected_tardiness: logged as warning
  • estimated_cost: total $/hour

Running-job awareness

For RUNNING jobs, remaining epochs are extrapolated from progress ("5/20" → 15 left) so the optimizer knows real remaining work, not full job cost.

End-to-End Tests (1 prod GPU + 1 prof GPU)

#ScenarioResult
1 Tighter deadline wins GPU (same priority) ✓ Optimizer picks tight-deadline first
2 No oversubscription with 3 jobs on 2 GPUs ✓ 1 per GPU, 1 waits
3 High-priority urgent job preempts low-priority ✓ Low-pri PREEMPTED, urgent runs
4 Past-deadline job flagged ✓ "will miss deadline by 0.7h"
5 Preempted job resumes from checkpoint ✓ Was 1/20, resumed at 2/20

Bugs found & fixed during testing

  • bug free_nGPUs must subtract currentScheduling usage — was reporting full capacity, confusing the optimizer
  • bug Race: preempted container still alive when next cycle fires → 3s wait after preemption under schedule_lock
  • bug DB pool exhaustion — connections held during whole job lifetime → split into phases, short-lived connections
